# Jellyfish and site theme handoff

This checkpoint preserves the current implementation for further review. It is a static, framework-free website served from the repository root. The animation is an original procedural WebGL effect; it does not use Three.js, external assets, a physics engine, or a video. The latest creative request was to improve swimming and remove content-dimming halos. The user has not yet given feedback on that latest iteration, so treat its visual quality as an open question rather than a finished design.

## Where to start

- `index.html` places an `aria-hidden` canvas in the homepage hero and loads the shared renderer. The existing name, introductory text, portrait, navigation, and page content remain real HTML.
- `js/jellyfish.js` owns scene setup, the character atlas and shaders, procedural geometry, swimming and spring-chain simulation, pointer response, quality adaptation, and cleanup. It selects the desk configuration from the canvas's `data-scene` attribute.
- `style.css` defines the homepage's atmospheric background, canvas layering, portrait and responsive layout. `theme.css` holds shared dark and light color tokens. `js/site.js` implements the public theme control; `js/theme-preference.js` and `hub/tools/operations-desk/theme.js` apply saved preferences on other pages.
- `hub/tools/operations-desk/index.html` and `desk.css` place a separate decorative canvas in the overview and a small 2D mirror in the repository-library heading. The desk's interactive explorer remains in `.scene-wrap` and uses its own `#graph` canvas and existing `scene.js` implementation.
- `functions/_lib/paths.js` and `test/blocked-paths.test.mjs` prevent repository documentation and other non-public files from being served by the site's root deployment. `changelog.json` records the user-visible changes. The Connect page is generated by `scripts/build-connect.mjs`; keep its output and generator consistent.

## Rendering and movement

A single WebGL point draw renders the school from a local canvas-generated atlas of binary digits, symbols, and hexadecimal characters. Geometry and per-character metadata are generated once using seeded randomness. The homepage uses five organisms, and the desk uses three. Particle counts are 8,000 on larger home displays, 5,000 on smaller or low-core devices, and 3,000 on the desk. The code maintains a dynamic buffer of interpolated strand positions rather than creating individual DOM nodes or draw calls.

Each organism has its own heading, momentum, contraction phase, size, depth, and slowly changing intent. A pulse applies thrust along the bell's heading; low-frequency procedural value noise adds water motion, and boundary and proximity forces steer the animals. Heading is constrained to avoid abrupt inverted spins. Thirty-two strands per organism each have seven spring-driven segments. Their anchors are projected from moving points on the bell; the character positions interpolate the simulated segments. The shader deforms the bell and adds restrained depth and lighting. Because the heading is constrained and propulsion is predominantly upward, some trajectories may still feel more upward-biased than fully free roaming; observe long enough to judge turns and passive downward drift.

The renderer has no content-proximity masks. The portrait naturally covers what is behind it, and foreground HTML stays above the decorative canvas. Bright particles may still compete with text or navigation when they cross it; this is a visual tradeoff to evaluate without reintroducing the dark halos the user rejected. The homepage canvas extends 14rem beyond the hero and fades at its edges. The radial atmosphere should blend into the page background; check for visible boundaries at different viewport sizes.

## Layout and visual direction

The user wants the existing dark, near-black and charcoal palette with off-white and restrained icy-blue/cyan accents, without a redesign. The default is dark; the public command palette can save an explicit light preference. The script-free Connect page defaults to dark and does not read the saved light preference. The animation is hidden in the explicit light theme.

Preserve the original masthead grid and portrait relationship: the portrait is 220px wide on desktop/tablet, aligns with the name, and becomes 160px above the text at the existing 640px mobile breakpoint. The canvas is out of flow and must not change layout or intercept clicks. Avoid covering content with opaque panels, adding decorative interfaces, or reintroducing opacity masks around text, navigation, or the portrait.

The user has repeatedly described earlier versions as too static, rigid, particle-cloud-like, artificially masked, or disconnected from believable swimming. The latest version addresses those complaints with constrained heading, pulse-driven propulsion, attached spring strands, stronger rim density, and no masks, but subjective visual approval is still pending. Check whether tentacles visibly bend and lag during turns, the bell remains recognizable, characters stay legible, movement is not repetitive, and the composition stays readable on mobile. The clip used for the last review is a local browser capture outside the repository and is not part of this checkpoint.

## Operations Desk boundaries

Decorative rendering is restricted to the clipped overview and repository-heading canvases, with `pointer-events: none`; it is never inserted into or over the explorer stage. The small heading canvas copies the overview render via a 2D context rather than starting another WebGL renderer. The engine pauses decorative rendering while the explorer is hovered or focused, then resumes it. Preserve the explorer's canvas, controls, camera, and existing appearance. The desk's live authenticated repository API could not be exercised with the simple static server; previous browser checks used mock repository responses. Verify real authenticated behavior in the appropriate local environment before claiming an end-to-end pass.

## Performance and accessibility

The effect uses one WebGL context and one point draw per page, a shared atlas within that context, bounded simulation steps, reduced particle counts for smaller/low-core devices, a capped device pixel ratio, and an adaptive resolution scale. It pauses when the relevant region is offscreen, the document is hidden, the light theme is selected, or the desk explorer is active. Reduced-motion users see a still frame. If WebGL is unavailable or initialization fails, the canvas is hidden and ordinary page content remains usable. Context loss/restoration and buffer, texture, program, animation-frame, and observer cleanup are handled in `js/jellyfish.js`.

A desktop browser observation in the preceding work ran for over 60 seconds; sampled organisms changed positions and contraction phases, and strand data changed over time. That is not a substitute for review by eye or for tests on physical devices. Rendering cost and battery use on real mobile hardware remain unmeasured. A local browser's simple static server cannot provide the desk's authenticated API or other server-side Functions.

## Local development and checks

From the repository root:

```sh
python3 -m http.server 8765
```

Open `http://localhost:8765/`. This previews static assets only; it does not run the authentication, storage, or repository APIs. Consult `DEPLOY.md` and the relevant tool documentation for the project's existing local Functions workflow, without copying credentials into this file.

Run the existing automated tests and basic checks:

```sh
node --test test/*.test.mjs
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s test -p '*hurricanes*.py'
node --check js/jellyfish.js
git diff --check
```

There is no root package build, lint, or type-check command for this static site. In a browser, inspect desktop, tablet, and mobile; watch motion for at least 60 seconds; test cursor and click interaction, keyboard navigation, reduced motion, WebGL fallback/context restoration, and page visibility. For the desk, confirm that the explorer and its controls remain untouched, decorative rendering pauses during interaction, and repository cards work with a properly configured local API or mocks. Do not commit browser logs, captures, secrets, local environment files, or generated scratch artifacts.
